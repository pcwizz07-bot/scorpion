# Scorpion — SC-015: Pi Node Agent rewrite

Date: 2026-09-15 · Task card SC-015. Server side (Phase A) is DONE and deployed; this is the node side.

## Goal
Replace `pi/agent.py` with a reliable node agent that talks to the Phase A FastAPI backend.
Fixes the verified PoC-killers:
1. **Data loss on link drop** — old agent dropped observations on HTTP failure. New agent keeps a persistent local spool (sqlite3) and replays with backoff.
2. **No location source** — new agent can use GNSS (SIM7600 HAT) per observation, with provisioned lat/lng fallback.
3. **Config from file** — old code hardcoded IPs + env-only. New: `/etc/scorpion/agent.conf` (JSON) + env overrides + provisioning flow (register via `X-Provisioning-Token`, store device token).
4. **Provisioned identity** — old open self-registration. New: node registers once, keeps device_id+token in state file (chmod 600).

## Non-goals
- WireGuard (Phase B — app must be transport-agnostic; server URL is just a string).
- RF chain changes beyond keeping the existing gr-gsm + IMSI-catcher mechanism.
- No new non-stdlib Python deps on the node (stdlib only: urllib.request, sqlite3, threading, json, re, socket, subprocess, signal).

## Layout (under pi/, stdlib only)
```
pi/
  agent.py              (entry: reads config, starts threads, signal handling)
  node/
    __init__.py

    capture.py          (grgsm_livemon + simple_IMSI-catcher txt tail reader → spool; SA freq scan)

  tests/
    test_config.py
    test_spool.py
    test_transport.py   (against a local http.server fake)
    test_capture.py     (txt tail parsing: new lines, truncation reset)
```

## Protocol (matches deployed backend)
- Provision: `POST {server}/api/v1/devices/register` header `X-Provisioning-Token: <token>`,
  body `{name, lat, lng, firmware_version}` → `{device_id, device_token}` (persist both; token hash server-side).
- Heartbeat thread: `POST {server}/api/v1/devices/{id}/heartbeat` header `X-Device-Token`.
- Observations: `POST {server}/api/v1/observations` header `X-Device-Token`,
  body `{"observations":[{imsi,mcc,mnc,country,brand,operator,signal_dbm,observed_at,...}]}`, max 200 per request.
  Response `{created, duplicates}`. On 401 → clear token, re-provision (if provisioning token present), re-queue.
  On 5xx/network error → leave in spool, exponential backoff (1s→60s).
  Duplicate handling is server-side; client must not drop anything it couldn't confirm.
- `observed_at` = capture time ISO-8601 UTC with tz.

## Capture
Keep the proven mechanism: `grgsm_scanner` (SA bands) → pick strongest → `grgsm_livemon -f <freq>`
→ `simple_IMSI-catcher.py -s --txt /tmp/imsi-output.txt` (Oros42, installed at /opt/dungbeetle-scanner by installer).
Parser: robust txt tail (track inode + offset; truncation → reset offset; parse CSV lines; strip spaces;
validate digits 5–20; build observation payload with device name/id + GNSS fix if available; push to spool).
Do NOT block capture on network.
