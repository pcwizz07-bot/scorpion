# Scorpion — SC-040: Isolate pytest from the dev database

Date: 2026-09-15 · Task card SC-040 (ready, plan-only until now).

## Problem (verified 2026-09-15)
`backend/tests/conftest.py` sets `DATABASE_URL` to the dev database `scorpion`
and its autouse `fresh_schema` fixture runs `Base.metadata.drop_all` +
`Base.metadata.create_all` against it. Every pytest run WIPES all migrated
tables (devices, imsi_observations, tracked_imsis, alerts, audit_log) and
leaves `alembic_version` stale, so the live dev server 500s and
`alembic upgrade head` becomes a no-op. Confirmed broken today.

## Fix (scope: backend/tests only — do NOT touch app code, .env, alembic/)
1. Point the test DB at a separate database: `scorpion_test`
   (postgresql+psycopg://scorpion:<redacted>@127.0.0.1:5432/scorpion_test).
2. In `conftest.py`, ensure the `scorpion_test` database exists before the
   engine connects (connect to the `postgres` maintenance DB and
   `CREATE DATABASE scorpion_test` if missing; the container user is
   superuser). Do this once, robustly (catch already-exists).
3. `fresh_schema` drop_all/create_all must then only ever touch
   `scorpion_test`. The dev DB `scorpion` and its alembic stamp must be
   left completely untouched by pytest.
4. Keep test env values fake/generated exactly as today (no real secrets).
